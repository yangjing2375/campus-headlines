## 四、缺陷与修复摘要

| 缺陷 | 根因 | 修复方式 | 状态 |
| --- | --- | --- | --- |
| BUG-01 越权查看未发布文章 | 详情接口只判空不判状态 | `ApiUserController#articleDetail` 增加 `status != 2 → 404` | 已关闭 |
| BUG-02 分页参数越界 | 分页参数直接透传，`current=-1` 生成负 offset | 新增 `PageUtil` 归一化（current ≥ 1，1 ≤ size ≤ 50），三处分页统一调用 | 已关闭 |
| BUG-03 删除被引用频道 500 | 只调 `deleteById`，依赖数据库外键报错 | `ChannelServiceImpl#delete` 前置统计文章数，> 0 抛业务异常 | 已关闭 |
| BUG-04 点赞并发丢失更新 | 「查旧值 → 内存 ±1 → updateById」非原子 | 改为 `setSql("like_count = IFNULL(like_count,0)+1")` 原子更新 | 已关闭 |
| BUG-05 阅读量并发丢失更新 | 同上 | `incrementView` 改为数据库端原子自增 | 已关闭 |
| BUG-06 上传仅校验扩展名 | 只比对后缀，不看文件头 | 增加 magic number 校验（jpg / png / gif / mp4） | 已关闭 |
| BUG-07 存储型 XSS | 正文按 HTML 原样输出，无白名单过滤 | 待引入 Jsoup 白名单清洗 | 遗留 |
| BUG-08 密码 MD5 无盐 | 初始化数据沿用 MD5 | 待迁移 BCrypt（登录时兼容旧哈希并按需升级） | 遗留 |

修复点在代码中以 `缺陷 BUG-xx` 注释标记，可用 `git grep "缺陷 BUG-"` 定位。

## 五、遗留问题与风险

| 编号 | 风险 | 影响 | 缓解 / 规避 | 计划 |
| --- | --- | --- | --- | --- |
| BUG-07 | 富文本正文可注入脚本 | 管理员 / 审核人打开详情可能被窃取 Cookie（Session 鉴权场景） | 演示环境仅本地运行、不对外开放；不打开来源不明的稿件 | 下个迭代引入 Jsoup `Safelist` 服务端清洗 + 前端 `c:out` 转义 |
| BUG-08 | MD5 无盐可被彩虹表反查 | 口令泄露后可被快速还原 | 口令均为演示账号（123456）；正式使用前统一重置 | 迁移 BCrypt，登录成功时平滑升级哈希 |

两项均已登记为 GitHub Issue（标签 `bug` / `security`），保留在缺陷库中便于追踪。

## 七、结论与建议

1. **功能层面**：三端核心链路（写稿 → 审核 → 发布 → 互动）完整可用，状态机流转（文章 0/1/2/3/4、话题 0/1/2/3）与设计一致，74 条用例回归后 72 条通过。
2. **质量层面**：本次最有价值的发现集中在「权限」「并发」「输入校验」三类。这三类问题在只做页面点击（黑盒功能测试）时几乎不会被发现，是本次测试设计（等价类 + 边界值 + 场景法 + 安全用例）的直接产出。
3. **改进建议**：
   - 把「未登录 / 低权限访问未发布资源」列为接口测试固定检查项，可覆盖大部分越权类问题；
   - 计数类字段统一使用数据库原子更新，禁止「读-改-写」；
   - 所有字符串入参统一做长度与内容校验，富文本必须白名单清洗；
   - 建议把本次固化的 JUnit 用例纳入每次提交（GitHub Actions），防止回归。
